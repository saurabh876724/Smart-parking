0. Design Principles and Decisions
 Separate perception from business logic. The AI layer only emits facts ("track 17 is inside slot A3",
"plate reads MH20AB1234, conf 0.91"). The Parking Intelligence Engine turns facts into meaning
(sessions, fees, violations). You can swap YOLO versions or OCR engines without touching billing.
 Two camera roles, not one. Plates are only readable when the plate is roughly 100+ px wide and the
vehicle is slow and close. A wide-angle camera over 50 slots can detect occupancy but usually cannot
read plates. GATE camera: entry/exit and ANPR. LOT camera: slot occupancy and violations. For a
one-camera student demo, one video can play both roles if vehicles pass close to the camera at the
entrance.
 Run ANPR only when needed. Detection and tracking run continuously. Plate detection and OCR run
only for vehicles in the gate zone, on the best few frames per track. This is the biggest saving on a 6 GB
GPU.
 Modular monolith first, services later. Start with one deployable app with clean module boundaries
and interfaces (EventBus, Repository, OCREngine). Split into processes/containers only when a measured
need appears.
 Store events, not frames. Persist state changes (slot FREE→OCCUPIED, session start/end, violations),
not per-frame detections; otherwise the database grows by millions of rows per day.
 Everything is confidence-aware. Low-confidence plates, ambiguous tracks and uncertain slots go to a
NEEDS_REVIEW / UNKNOWN state instead of silently producing wrong billing.

A. High-Level Architecture
 Figure 1 – End-to-end architecture: cameras → AI worker → event bus → intelligence engine → database/API → dashboard
Real-time flow in one paragraph
Each camera has a grabber thread that keeps only the newest frame (dropping old ones), so latency never
accumulates. The inference loop takes that frame, runs YOLO and the tracker, and updates slot state
machines and gate logic. It emits small JSON events on the bus. The Parking Intelligence Engine consumes
them, writes to PostgreSQL, and pushes updates over WebSocket. Video goes to the browser separately from
metadata: the frontend draws slot overlays from WebSocket data.

 Figure 2 – Debounce state machine. Thresholds live in config, not code.
Freeing takes longer than occupying because a false FREE (which lets the system double-assign a slot) is
worse than a delayed FREE.
Overlap metric. Use the vehicle's ground footprint (lower ~40% of the bounding box) since the top of a car
in an angled view overlaps neighbouring slots. Score = area(footprint ∩ slot_polygon) / area(slot_polygon).
Assign each vehicle to at most one slot (greedy or Hungarian by highest score). A vehicle with significant
overlap (>0.2) on two slots is a “parked across lines” violation.
Occlusion rule. If a parked vehicle's track is lost while inside a slot, and no track exits the slot region, hold
OCCUPIED. Only release after the FREE timer and no occlusion evidence. An optional second opinion later is
a small slot-crop classifier (occupied/empty, trainable on the public PKLot dataset).
Identity design. Tracker IDs are temporary, per camera, and reset on restart. Real identity comes from the
plate. The system keeps track_id → plate → session_id bindings in memory and persists them in the session
row. If a track is lost and re-acquired, the plate re-attaches it to the same session.

C. Data Flow: End to End
 Figure 3 – Sequence: vehicle enters → plate read → slot occupied → exit → session closed
Step by step
 1. Vehicle enters view. The grabber delivers the latest frame. YOLO returns boxes for {car, motorcycle,
bus, truck}. Detections below the confidence threshold (start at 0.35) are dropped; detections outside the
ROI mask are ignored.
 2. Tracking. ByteTrack matches detections to existing tracks (Kalman + IoU) and assigns track_id=17.
Its trajectory (centroid history) is kept in a short ring buffer.
 3. Gate event. The centroid crosses the virtual ENTRY line in the configured direction →
VEHICLE_ENTERED. Direction uses the sign of the cross product so jitter near the line does not
double-count. Each track fires an entry event at most once (idempotency key camera_id + track_id +
event_type).
 4. Plate detection. While the track is in the gate zone, the vehicle crop goes to the plate detector at
~3–5 FPS. Each frame is scored by plate size, sharpness (Laplacian variance) and detector confidence.
The top-K crops are kept.
 5. OCR + validation. Per top crop: pad, upscale to ~64–96 px height, CLAHE, deskew, run OCR,
normalise (uppercase, strip symbols), apply position-aware character correction, check the per-country
regex. Then weighted vote across frames: accept when the same string wins ≥2 times with average
confidence ≥0.80. Otherwise keep collecting until the vehicle leaves the gate zone; if still uncertain, mark
NEEDS_REVIEW with the best crop saved.
 6. Session creation. The engine creates parking_sessions(status=ACTIVE, entry_time, plate_id,
entry_image). It checks the plate against blacklist/whitelist/reservations. A duplicate ACTIVE session for

 7. Slot assignment. When a slot FSM turns OCCUPIED and the occupying track is bound to a session,
the engine sets session.slot_id and opens a slot_occupancy_history row. If the track cannot be linked
(cross-camera handoff failed), the slot is still OCCUPIED with session_id = NULL – honest and correct for

 8. Exit. The vehicle leaves its slot (PENDING_FREE → FREE), then crosses the EXIT line or is last seen in

exit_time, duration = exit − entry, status=COMPLETED.
 9. Billing (optional). A tariff engine computes the fee (free minutes, hourly rate, daily cap, rounding)
and creates a payments row (PENDING). Gateway integration is a later feature; for the MVP “compute and
display” is enough.
 10. Dashboard update. Every step pushes a small WebSocket message; the UI updates slot map,
counters, history and alerts without polling.

Relationship notes
 license_plates vs vehicles: a plate is something the camera reads; a vehicle is a registered entity. Most
walk-in vehicles have a plate but no vehicles row, so sessions reference plate_id directly and vehicle_id is
nullable.
 parking_sessions ↔ parking_slots: many sessions over time per slot, at most one ACTIVE. Enforce with
a partial unique index: UNIQUE (slot_id) WHERE status='ACTIVE' AND slot_id IS NOT NULL. Also
enforce one ACTIVE session per plate.
 slot_occupancy_history: answers “how long was slot A3 occupied today” and heatmaps. Separate from
sessions because a slot can be occupied by an unidentified vehicle.
 detection_logs: an event/diagnostic log, sampled or partitioned by day, with a retention policy. Not a
per-frame dump.
 plate_hash: HMAC-SHA256 of the normalised plate with a server-side secret, used for lookups and
uniqueness. plate_encrypted (AES-GCM) holds the real text; the UI shows plate_masked unless the role
permits reveal.
 Indexes: (plate_hash); sessions (status, entry_time); slots (slot_id, status); logs (camera_id, ts); violations
(detected_at, status).

F. AI Pipeline
LOT camera inference loop
frame → ROI mask → YOLO(vehicles) → ByteTrack → footprint calc
      → slot assignment (overlap) → slot FSMs → state-change events
      → violation rules → events
GATE camera inference loop
frame → YOLO(vehicles) → ByteTrack → zone/line logic
      → for tracks in gate zone: plate detector (3–5 FPS)
      → quality score → top-K crops → preprocess → OCR
      → normalise → validate → multi-frame vote → PLATE_READ event

Practical accuracy advice: most real-world ANPR errors come from image quality (blur, angle, glare,
tiny plates), not the OCR model. Fix camera placement, shutter speed (fast, to avoid motion blur) and
IR/lighting before fine-tuning anything. Multi-frame voting typically gives a larger gain than a better OCR
model.
Inference settings for RTX 4050 6 GB: FP16, imgsz=640 (or 960 for distant small vehicles), small or
medium YOLO variant, inference every 2nd–3rd frame on the LOT camera (parked cars don't move fast), and
TensorRT export once things work.
Licensing: Ultralytics YOLO is AGPL-3.0 – fine for a student project. If you commercialise, buy the enterprise
licence or use a permissively licensed detector. Verify current terms.
